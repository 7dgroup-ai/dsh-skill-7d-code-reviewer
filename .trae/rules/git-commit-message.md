commit_rule:
  # 1. 基础语言与字符规则
  language: 简体中文
  font: 标准书面中文，禁止口语、网络用语、方言、语气词、情绪化描述
  charset: 纯文本，仅使用中文、数字、行业通用标准英文专有名词、中文全角标点
  char_spec:
    - 允许保留**行业通用技术专有名词**：Gateway、Docker、K8s、MySQL、Redis 等标准组件名称，不强行翻译
    - 禁止随意拼接英文单词、拼音、英文缩写、自定义简写
    - 禁止使用 emoji、颜文字、特殊符号：@ # $ % ^ & * ~ 等
  punctuation:
    - 正文统一使用**中文全角标点**
    - 提交标题（首行描述）**末尾禁止添加句号、逗号**

  # 2. 通用格式规范（强制遵循，对齐 Git 主流提交范式）
  format: "【类型】简短描述（可选补充详情）"
  max_length:
    title: 单行主标题不超过 50 个字符（中文/字母/数字均计为1个字符）
    detail: 详情内容单行不超过 70 个字符
  line_rule:
    - 简单改动仅保留**单行标题**，简洁优先
    - 复杂改动：标题与详细内容之间**必须空一行**，再补充详情
    - 多条改动内容统一使用「数字序号」逐条罗列，不混用多种符号
    - 详情段落较长时可合理分段，保持排版整洁

  # 3. 提交类型（固定分类，必选其一；新增合并类型，补充适用边界，区分易混类型）
  type_list:
    - 【新增】：新增功能、接口、页面、代码文件、配置项、脚本、路由规则、部署资源、测试用例
    - 【修复】：修复线上/测试 Bug、运行异常、报错、兼容性问题、逻辑错误、配置错误
    - 【优化】：性能调优、代码重构、逻辑精简、交互体验升级、架构优化、资源利用率提升
    - 【调整】：修改运行参数、环境配置、样式布局、界面文案、权限规则、路由顺序（侧重微调配置/展示）
    - 【删除】：彻底移除废弃代码、无用文件、下线接口、过期脚本、冗余配置、历史资源
    - 【文档】：更新注释、README、接口文档、部署手册、运维说明、使用指引、清理过时文档内容
    - 【测试】：新增/修改/删除单元测试、接口测试、联调用例、压测脚本、自动化测试代码
    - 【回滚】：版本回退、撤销历史提交、恢复原有代码/配置/文档（仅用于撤销已上线改动）
    - 【合并】：分支合并、解决代码冲突、同步分支代码、合入特性分支（分支场景专用）

  # 4. 语义、句式与追溯标识规范
  wording_rule:
    - 句式统一使用**动宾短语**，采用客观陈述句，不使用祈使句、将来时态、主观评价
    - 描述要求：必须写明「改动对象 + 具体动作」，拒绝模糊表述（如：改代码、调配置、修复问题）
    - 范围标注：涉及多环境/多服务时，明确标注环境（开发/测试/预发/生产）或服务名称（网关、订单服务等）
    - 追溯格式（多人协作必填，统一位置：标题末尾/详情末尾）：
      - 关联需求：关联需求ID-XXX
      - 关联工单/缺陷：关联工单ID-XXX / 关联缺陷ID-XXX
    - 禁止内容：自问自答、吐槽、备注临时想法、未完成标记（如：待优化、后续再改）

  # 5. 场景细分描述规则（全覆盖：代码、前端、配置、数据库、运维、容器、网关、文档等）
  scene_detail:
    code: 业务代码优先注明「模块/服务/类/函数」+ 具体动作
    frontend: 前端改动注明「页面/组件/样式/交互」+ 调整内容
    config: 配置改动注明「配置文件/环境变量/开关项」+ 修改内容与生效环境
    db: 数据库改动注明「数据表/字段/索引/执行脚本」+ 新增/修改/删除动作
    gateway: 网关改动注明「路由/过滤器/限流规则/转发策略」+ 具体调整内容
    container: 容器/Docker/K8s改动注明「镜像/编排文件/资源配额/挂载/网络」+ 动作
    deploy: 部署/CI/CD改动注明「流水线/启动脚本/部署流程/镜像版本」+ 修改内容
    script: 运维脚本改动注明「脚本用途/执行逻辑/路径」+ 优化/修复/调整内容
    docs: 文档改动注明「文档名称/章节/内容模块」+ 更新/补充/移除动作

  # 6. 提交拆分与行为规范（避免大杂烩提交，保障版本追溯）
  split_rule:
    - 单次提交**禁止混合多个无关大功能**，跨模块、跨类型的改动必须拆分为多次提交
    - 代码改动与纯文档改动建议拆分提交；紧急热修复单独提交，不夹带新功能
    - 批量清理废弃内容统一归类为【删除】，配套文档同步清理可在同一条目详情中说明

  # 7. 严格禁用规则（红线要求）
  forbidden:
    - 禁止不添加类型标签、私自修改【类型】标签格式
    - 禁止纯英文、无意义拼音、自定义缩写、中英随意混搭（行业标准专有名词除外）
    - 禁止语句不通顺、语义模糊、内容空洞的提交描述
    - 禁止在提交信息中添加临时备注、待办事项、个人情绪、闲聊内容
    - 禁止超长堆砌内容、滥用特殊标点、换行混乱
    - 禁止跨服务、跨业务的无关改动合并为一次提交

  # 8. 标准示例（分场景：基础业务 + 网关/容器/部署/运维/文档，含你指定场景）
  examples:
    # 基础业务场景
    - 【新增】用户模块新增手机号登录接口
    - 【修复】修复列表分页数据加载异常问题
    - 【优化】重构公共工具类，提升代码执行效率
    - 【调整】修改首页弹窗展示时长与样式
    - 【删除】移除旧版废弃的统计代码文件
    - 【文档】补充支付模块接口注释与使用说明
    - 【测试】新增订单结算场景单元测试用例
    - 【回滚】回退上一版用户权限配置改动
    - 【合并】合并开发分支至主分支，解决代码冲突

    # 网关 / 微服务场景
    - 【新增】网关新增第三方服务路由转发规则
    - 【修复】修复网关请求转发超时异常
    - 【优化】优化网关过滤器执行逻辑
    - 【调整】修改网关限流阈值与监听端口

    # 容器 / Docker / K8s 部署场景
    - 【新增】编写网关容器启动编排脚本
    - 【修复】解决容器启动端口占用问题
    - 【优化】调优容器CPU与内存资源配额
    - 【删除】移除测试环境废弃容器配置文件

    # 文档专项（含你原需求：移除废弃网关容器部署内容）
    - 【文档】更新文档，移除废弃的网关容器部署相关内容
    - 【文档】修订生产环境容器部署操作手册
    - 【文档】补充网关运维故障排查说明

    # 带追溯工单场景
    - 【新增】购物车新增批量结算功能 关联工单ID-1024
    - 【修复】修复商品金额计算精度问题 关联缺陷ID-089

    # 复杂改动（标题+空行+多行详情 标准格式）
    - 【文档】全面更新部署相关文档

      1. 补充新版容器集群部署流程
      2. 移除已下线的网关容器部署章节
      3. 修正原有文档配置描述错误
    - 【优化】优化网关容器运行性能

      1. 调整容器日志切割策略，降低磁盘占用
      2. 优化路由匹配逻辑，提升转发响应速度
