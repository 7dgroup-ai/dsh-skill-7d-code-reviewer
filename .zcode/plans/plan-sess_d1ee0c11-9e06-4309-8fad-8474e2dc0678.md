# 编写《独立仓库 dsh 插件开发实战教程》

## 产出物

新建 **`docs/plugin-development-tutorial.md`**（仅中文、单文件，约 700–900 行），体例参照 Cordis 教程：开篇定位 + 准备工作 + TypeScript 说明 + 递进章节（每章给出确切文件内容、命令与预期输出，穿插"尝试制造错误"）+ 结尾"从这里走向"。

同时在 `README.md` 与 `README.zh.md` 各加一行指向本教程。

叙事主线：**从零构建一个最小 skill 插件包，逐章长成与本仓库同形的完整 bundle**。Cordis 教程第 7 章在 `ctx.tools` 上注册了工具，本教程是同一模式的延续——把一个 skill 经 `ctx.skills.registerProvider` 注册，并打包成可被 `dsh plugin add` 启用的独立仓库组合包。

## 教程结构

**前言与准备工作** — 定位（面向要开发自己 dsh 插件的工程师；假设读者读过 Cordis 教程第 1/3/7 章或等效）；前置条件（Node ≥22.19、pnpm 10+、dsh CLI）；建一个全新工作目录 `dsh-skill-my-skill/` 作为各章的实验场（对应 Cordis 教程的 `tmp/cordis-tutorial`）；TypeScript 说明（类型注解 / `import type` / 声明合并三点，只讲本教程用到的部分）。

**章节**（每章以 vitest 为运行载体——在测试里 `new Context()` 挂载 SkillRegistry 再挂载插件，这正是本仓库 tests/ 的真实模式；安装类章节用 dsh CLI）：

1. **最小插件包** — `pnpm init` 起骨架：package.json（type: module / exports / files / scripts）、最小 `src/index.ts`（`name` / `inject: ['skills']` / `apply`）注册一个只含 name/description 的 skill；装 peer 镜像 devDependencies；第一个 vitest 断言 `ctx.skills.list()` 出现该 skill。运行 `pnpm test` → 预期输出 1 passed。*尝试制造错误：把 inject 写成不存在的服务名，观察插件静默 PENDING——衔接 Cordis 教程第 6 章的 fiber 诊断。*
2. **manifest 与组合层** — 加 `dsh.bundle.patch` 键与 `cordis.patch.yml`（insert 行按包名引用）；讲透普通依赖包 vs 组合包的判别；`exports` 里的 `./cordis.patch.yml` 子路径与包名自引用；`files` 清单。验证：测试里 `import * as pkg from '<自己的包名>'` 成功（Node exports 自引用）。
3. **插件代码与能力面** — 长成真实形态：`SkillCandidate`/`SkillProvider`（`list()`/`get()`）、`registerProvider` 返回 disposer（衔接 effect 概念：卸载即注销）、`INVOCATION`/`BUNDLED_SKILL_RANK`/`source: 'bundled'`；测试断言 get() 读到正文、dispose 后 list() 为空。引用本仓库 `src/index.ts` 真实代码分段讲解。
4. **资源定位与不变量入口** — `new URL('../assets/…', import.meta.url)` 为什么按 lib/ 产物布局算层级；`resourceBase: { kind: 'directory' }`；assets/ 组织（SKILL.md 正文 + references/ + templates/）与资源完备性测试；第二个能力面示例：`src/invariant.ts`（`inject: ['invariants']`，空 installer 的语义）与 `@deepseek-ai/dsh-invariants` peer。
5. **自包含构建** — pnpm git 安装四步流程（克隆→装依赖→prepare→打包缓存）为什么决定 prepare 必须自包含；tsdown.config.ts 逐项讲解；*尝试制造错误：`fixedExtension` 用默认值 → 产出 .mjs 与 manifest 的 lib/index.js 不符；`workspace:^` 依赖在 git 安装时必炸的机制*；lib/ 必须 gitignore。
6. **本地试装与迭代** — `link:` 试装即改即生效；`dsh --dump-config` 两层验证（应出现 `# == <包名>` 层与挂载行）；`DSH_HOME=/tmp/…` 隔离环境用 `git+file://` 做真实安装演练，走完 allowBuilds 两步。
7. **分发与消费者授权** — git / npm / tarball 三形式对比表；allowBuilds 的安全边界语义（安装时在你机器执行、键含 commit sha、上游更新需重新授权是特性）；pin `#<sha>`；`pnpm publish` 前构建好 lib/ 与 publishConfig。
8. **常见坑与排错** — 首条对齐用户总结的 6 条（workspace: 协议 / .mjs 扩展名 / prepare 引用 monorepo 上下文 / lib/ 入 git / 组合层行名与 id 冲突 / 缺 exports 字段的自引用失败），每条附一句原理；再加 Cordis 侧排错（PENDING 静默、模块解析失败走 logger 不崩溃）。

**从这里走向** — 指回本仓库作为完整可运行样例；Cordis 教程后续阅读（构建工具 / 三层能力设计 / cordis-surface 区块 / examples/headless-agent）；贡献迭代循环（第 6 章的工作流即日常循环）。
